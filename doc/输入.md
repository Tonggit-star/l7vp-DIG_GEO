## 追加确认

### 1. 数据行存储格式

方案 B "列值用 JSON"——我理解是：每个 Excel 行存一条数据库记录，一个 JSON 字段存储该行的所有列值，例如：



```
数据行表:
  row_id | dataset_id | row_data (JSON)
  1      | ds_001     | {"城市":"北京","人口":21540000,"GDP":41610}
  2      | ds_001     | {"城市":"上海","人口":24870000,"GDP":44652}
```

可以这样，但是json中这些字段名会不会太占地方，需不需要单独存到其他子表？这样只需要一条记录，关联查询即可。

### 2. 图标"库号"和"代号"

这是本次的核心概念，我想确认理解是否正确：

- **库号** = 图标所属的库/分类标识（类似当前的一级分类名，如 `默认`、`通信`）通常是一个数字（字符串类型就行，说不定也用汉字）
- **代号** = 该分类下每个图标的唯一标识，通常也是一个数字（字符串类型就行，说不定也用汉字）
- 图层中使用时，数据里两个字段分别指定库号和代号，就能精确定位到一个图标

举例：数据中 `库号=通信, 代号=antenna` → 渲染成通信分类下的 antenna 图标；同一图层另一条数据 `库号=通信, 代号=tower` → 渲染成 tower 图标。

是这样的。库号和代号是用户自定义的，给两个输入框，让用户输入，保存在数据库。

### 3. 图标存储方案推荐

我推荐 **文件系统存储 + 数据库记录元数据** 的方式：

| 层       | 方式                                                   |
| -------- | ------------------------------------------------------ |
| 图片文件 | 存文件系统，Java 静态资源直接 serve，性能好            |
| 元数据表 | 库号、代号、分类、文件名、原始文件名、大小、上传时间等 |

我觉得可以，这个文件系统存储指的是？直接放在服务器上？还是需要一个minio?我不希望依赖minio，这样软件部署起来太重了。

### 4. 瓦片配置

**只配一个默认地址**就行，我的内网除了那个瓦片，没有其他资源了，想用其他地图也没有。配完之后是持久化到数据库还是写回 `config.js` 文件都可以，根据你的工程经验来。

### 5. 图标按钮位置

是的，和新建项目按钮放一起。图标库管理和瓦片配置两个按钮都放这里。
